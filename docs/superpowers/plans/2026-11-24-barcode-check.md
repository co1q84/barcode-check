# 条码核验开发方案

**目标** 实现 [首版界面设计](../../../README.md#首版界面设计) 和 [产品约定](../../../PRODUCT.md)，从空白配置走通设置、连续扫码、异常处理和导出。

**技术栈** Windows 上的 Python 3.12 和 Tkinter。设置工作簿用 openpyxl，核验记录 CSV 和设置 JSON 用标准库处理。

## 模块和数据流

| 文件 | 职责 |
| --- | --- |
| `barcode_check/settings.py` | 不可变基表与分页设置。集中验证组合和前缀唯一性，按当前 Windows 用户保存 JSON。 |
| `barcode_check/batch.py` | 核验目标及规则快照、录入顺序、记录分页、重复拦截、有效数量和批次结束。 |
| `barcode_check/records_csv.py` | 导出原始条码、结果和批次目标。 |
| `barcode_check/settings_xlsx.py` | 基表 Excel 模板、数据导出和整批导入校验。 |
| `barcode_check/settings_ui.py` | 单表设置窗口、编辑和试扫、批量删除及 Excel 文件入口。 |
| `barcode_check/app.py`、`theme.py`、`__main__.py` | Tkinter 核验窗口、共享视觉样式及 `python -m barcode_check` 入口。 |

开始时从设置取规则快照，用于本批扫码判定。删除有效记录后从本批去重索引移除该码。设置通过完整配置验证后原子写入 `%APPDATA%\barcode-check\settings.json`，保存成功才刷新窗口数据。

## 首版取舍

- 前缀重叠时优先匹配最长前缀，设置试扫展示实际命中项。现场样本可以进一步核实前缀定义。
- 有应扫数量时，达到即显示「数量已齐」。超过上限的录入拦截并提示。结束时若数量不足，默认继续扫码，可主动确认以「数量不足」结束。结束后记录保留至开始新批或关闭窗口，两个入口都提供导出机会。
- 扫码异常留在本批记录中供回查。Excel 基表导入失败时直接显示行号和原因。基表字段和条码以文本处理，保留前导零。

## 实现与验收

- [x] **设置模型和持久化。** `Settings` 校验编码和厂家组合唯一及精确前缀唯一，`edit_row` 和 `delete_rows` 更新整行。`SettingsStore` 读取及原子保存。验证首次目录创建、有效往返、无效文件保留、过期写入和最长前缀。
- [x] **批次和条码文件。** `Batch` 统一执行规则匹配、重复拦截和数量边界。验证重复和超量优先级、无目标、实际数量不足、删行后补扫、跨页导出及保留前导零。
- [x] **设置界面。** `SettingsWindow` 由主窗提供设置快照和保存回调。验证单表的增改、搜索、批删、试扫、Excel 模板和数据导出、有效导入及失败后无写入。
- [x] **核验主界面。** 验证可调整窗口、厂家下拉、数量状态、扫码回车、超量对话框、结束与换批、倒序分页、按行删除、导出及返回扫码焦点。
- [x] **交付。** 全量运行 `python -m unittest discover -s tests -v`，从模块入口启动，并实际检查默认、最小和最大化窗口的扫码、异常、记录与设置。README 提供启动和文件格式说明。

Windows 窗口验证使用演示数据和模拟键盘录入，现场可用真实扫码枪与条码样本核对回车提交和规则命中。
